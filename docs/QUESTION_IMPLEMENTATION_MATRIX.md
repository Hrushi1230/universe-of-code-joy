## Audit rules

1. Every question in `problems.ts` appears exactly once below. A test enforces completeness, uniqueness, algorithm ownership, frame family, and current module status.
2. `Ready` means only that a compatible visualizer module resolves today. It does not mean the full Golden learning loop is complete.
3. `Missing` is an implementation gap for Phases 4–5. It must not be hidden by routing a question to an educationally incorrect module.
4. Binary Search remains the locked visual and behavioural reference. Its seven questions resolve through the shared module or one of six question-specific modules.
5. Large production constraints do not define visual input size. Teaching presets use the safe limits below so the desktop page, left world, right code/reasoning panel, and bottom playback band remain fixed.
6. The visualizer page, world, code, reasoning, timeline, and auxiliary panels do not scroll. Inputs and visible phase counts are capped to fit their frozen boxes.
7. Nodes and cells never shrink below readable size merely to fit more data. Inputs beyond the teaching limit are rejected or summarized before rendering. Visualizer boxes never scroll.

## Family contracts and safe visible limits

| Family              | Primary world                            | Required state and auxiliary data                                                   | Prediction / trace focus                             | Safe teaching viewport                                        |
| ------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------- |
| Arrays / searching  | `array`                                  | indices, target, current pointer, active range, comparison                          | next pointer or boundary; execute one comparison     | Hard limit: 12 cells                                          |
| Two pointers        | `array`                                  | left/right/read/write pointers, pair or aggregate, excluded region                  | choose pointer movement; update one pointer          | 12 visible cells                                              |
| Sliding window      | `array`                                  | left/right bounds, current/best value, frequency or zero budget                     | expand vs shrink; update window state                | 12 visible cells; strings render as indexed characters        |
| Sorting / selection | `array`                                  | comparison pair, pivot/key, swap/write, sorted partition; optional stack/log        | choose compare/swap/partition action                 | 12 visible cells; recursion stack shows 8 frames              |
| Stack / queue       | `stack` or `queue`                       | top/head/tail, operation, active token, secondary structure when needed             | push/pop or enqueue/dequeue; execute one operation   | 8 visible entries per structure; summarize hidden entries     |
| Linked list         | `linked-list`                            | nodes, `next` links, head/tail/current/prev/slow/fast, detached link                | choose pointer/link mutation; execute one mutation   | Hard limit: 8 nodes                                           |
| Trees / BST / heap  | `tree` with array companion where useful | stable node positions, path/current/frontier, recursion/queue, heap index           | choose branch/visit/swap; execute one traversal step | Hard limit: 15 nodes and 4 levels; heaps use at most 12 slots |
| Graphs              | `graph`                                  | stable nodes/edges, visited/frontier/current, queue/stack, distance/parent/indegree | choose next node/edge; execute discover/relax/union  | Hard limit: 10 nodes and 16 edges                             |
| Grids               | `grid`                                   | row/column, visited/frontier, component/path, queue/stack                           | choose neighbor; execute visit/backtrack             | Hard limit: 8 × 10 cells                                      |
| Hashing             | `table` plus source values               | key/hash/bucket, frequency/group, collision chain                                   | choose lookup/update bucket; execute insert/count    | 8 buckets and 8 visible chain items; summarize overflow       |
| Dynamic programming | `table`                                  | base cases, active cell, dependencies, formula, candidate/write value               | choose dependency/formula; compute one cell          | Hard limits: 1-D 12 cells; 2-D 8 × 10 cells                   |

Auxiliary stack, queue, key-value, log, and cost panels show at most 8 rows and summarize additional logical entries as `+N more` without scrolling.
